# Report template (English)

Readers are sellers without a technical team. `audit.py` has already written `data/report.draft.md` in this shape; edit the draft, do not start from scratch.

## Writing rules (for the agent)

- Conclusion first, short plain sentences. Gloss each platform on first mention: "Meta pixel (the tracking code for Facebook / Instagram ads)", "Google Tag Manager (GTM, a container that loads other tags)".
- Labels exactly: `[Verified]` `[Store claims]` `[Third-party]` `[Shown on page]` `[Inferred]` (followed by "Basis: ..." on the same line) `[Conflicting]` `[Not found]`. Label low rather than high.
- **Code on a page = [Shown on page], not "it is working"**. Only the user's screenshots or a browser test justify [Verified], with "Basis: your screenshot <file> (<date>)" on the same line.
- Not seen = "not seen on the pages checked [Not found]", never "not installed".
- No tracking IDs (pixel numbers, G- / AW- / GTM- IDs), code or technical words in the body (full list: `scripts/check_report.py`); IDs and verbatim source go to the appendix.
- The privacy section starts with "These are notes, not legal advice." and never says "compliant / non-compliant / illegal".
- The appendix states `Status: complete` (or partial / failed), equal to `status` in `summary.json`.
- Homepage unreachable (`failed`): a short report only (one line at a glance, open questions, appendix, fixed ending); the draft already has this shape.

## Structure

```markdown
# <domain> ad tracking audit report        (someone else's store: # <domain> ad tracking: public page observation)

<sub><url> · checked <YYYY-MM-DD> · <n> public pages, <m> Google tag containers</sub>

## At a glance

- <3-5 conclusions, each with a label>

| Platform | Code on page | Page views and add to cart | Purchases |
|---|---|---|---|
| Meta pixel | Yes [Shown on page] | needs a browser test [Not found] | needs your confirmation [Not found] |

**Do these 3 things first**
1. <...>

**What this report cannot see**: <one sentence>

## Platform status
## Duplicates and legacy
## Checkout and purchase: needs your input
<fixed Shopify checkout notes + what we need (ID / please send / what it proves / status)>
## Server-side events
## Privacy and consent notes
These are notes, not legal advice.
## Fix list
<grouped High / Medium / Low; each: check (platform): fix. Who: you, in the admin / a freelancer or theme developer / you, screenshots per the list>
## Open questions
## Appendix: evidence and sources
- Status: <complete/partial/failed>
<pages checked, tracking IDs found, problem IDs verbatim, pixels registered in Shopify, evidence table (E1-E6 only here)>
```

## Fixed ending (after the appendix, verbatim)

```markdown
---

### What this report does not cover

- Things only the ad platforms' admin can confirm: whether server-side events are on, whether deduplication works, match quality, enhanced conversions. Items you did not send a screenshot for are marked [Not found].
- We never enter checkout or place orders; checkout and purchase events can only be confirmed with your admin screenshots or a test order you place yourself.
- The privacy and consent part is a set of notes, not legal advice; ask a local professional whether you comply.
- This report is based on public pages only and is a snapshot of one day; store settings and platform rules change.

Browser tests, multi-store comparison, export reconciliation, or hands-on help: https://github.com/harrison-ming/chuhai-skills#advanced

<sub>Generated by tracking-audit (chuhai-skills)</sub>
```
