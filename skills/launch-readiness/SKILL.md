# 开店上线前体检

给准备上线 (或刚上线) 的出海卖家做一次体检: 一份大白话 PDF 报告 + 一张按优先级排好的 `整改清单.csv`, 每条写清 "在哪, 原文是什么, 怎么改, 依据". 读者多半不懂技术. 分工: 脚本抓页面, 判定规则, 写报告草稿; 你复核 (特别是前后矛盾), 改成通顺的大白话, 自检后交付.

## 边界 (先读)

- 只读公开页面. **不登录后台, 不进结账, 不下单, 不提交任何表单.** 请求之间留间隔, 不并发.
- **店铺开着密码页时不要索要店铺访问密码** (会进对话记录); 改走模式 P 或上线后重跑.
- **不给 "合规/不合规/违法/合法" 结论**: 页面事实标 `[已核实]`, 对照法规或官方要求的判断最高 `[推测]` + 依据. 报告不是法律意见.
- 非 Shopify 站: 只抓同一网站, 最多 40 页, 深度 2, 遵守抓取规则, 不跑 JavaScript; 结果最多 `partial`.
- 不做: 起草完整政策, 税务/VAT 登记判断, 广告追踪事件校验, 页面速度, 品类准入.

## 第 0 步: 检查 Python

脚本要用 Python 3.8+. 依次试, 用第一个输出 `Python 3.x` (x ≥ 8) 的命令, 下文的 `python3` 都换成它:

```bash
python --version
python3 --version
py -3 --version
```

- macOS / Linux 一般是 `python3`; **Windows 一般是 `python` 或 `py -3`**.
- Windows 输出 "Python was not found; run without arguments to install from the Microsoft Store..." (退出码 9009) 算**没有 Python**.
- 都不行: 用大白话教用户装 (Windows 命令行输入 `python` 打开应用商店点"获取", 或 python.org 下载并勾选 "Add python.exe to PATH"), 装好重开 AI 助手. 用户不想装就走模式 C.

## 第 1 步: 问清三件事 (说了就不问)

1. 店铺网址 (必填).
2. 卖哪些国家/地区 (选填). 没说: 用页面上能看到的市场加美国, 报告第一节写明, 不对可以重跑.
3. 打不打算投谷歌购物广告 (选填, 默认按"会投"检查; 不投加 `--no-ads`).

用户只问一句 "我的店能上线吗" 也直接开工, 不要来回确认.

语言: 用户用英文提问时, 所有脚本加 `--lang en`, 报告按 `references/report-template.en.md`; 否则中文.

## 第 2 步: 采集 + 判定 (按环境选模式)

脚本在本技能目录 `scripts/` 下, 只用标准库, 不用装包.

**交付位置**: 用户没指定时**不要加 `--out-root`**, 也不要写到当前目录; 脚本默认存到"文档/出海体检报告" (设置了环境变量 `CHUHAI_OUTPUT_DIR` 时用它). 所有模式都一样. 用户明确说了存哪才加 `--out-root <目录>`.

**模式 A (首选): 能跑 Python 且能联网**

```bash
python3 <技能目录>/scripts/audit_collect.py <网址> --markets "US,UK,DE"
```

脚本抓首页, 政策页, 3 个抽样商品页, 联系/常见问题页, 至多 3 个市场版本, 抓取规则和网站地图, 然后自动运行 `audit.py`. 最后打印**运行目录**, 数据在 `<运行目录>/原始数据/` (英文 `data/`).

- 打印 "店铺开着密码页": 停下, 告诉用户两条路: (a) 把后台政策文字, 常见问题, 联系方式, 商品导出表放进一个文件夹, 走模式 P; (b) 上线撤掉密码后重跑. 这一次仍要交付 (见第 5 步).
- 几乎全是网络错误 (不是 403/404): 环境不能联网, 换模式 B. 不要自己改脚本或换抓取方法绕过.

**模式 P (粘贴/导出): 店铺开着密码页, 或用户只想先查文字**

用户的文件放进一个文件夹 (文件名随意, 按名字和内容自动归类; 商品导出 CSV 来自 Shopify 后台 Products → Export). 用户直接在对话里粘贴文字时, 把每段存成一个 .txt 放进新建文件夹 (建在交付根目录下, 不要建在当前目录).

```bash
python3 <技能目录>/scripts/paste_ingest.py <文件夹> --name <店名或域名> --markets "EU,AU"
```

粘贴内容的事实标 `[店铺自称]`, 线上展示类检查记 `[查不到]`, 完成状态 `partial`.

**模式 B: 能跑 Python, 不能联网, 有网页读取工具** → 按 `references/method.md` 的"手动取数"把页面存进 `<运行目录>/原始数据/raw/`, 再运行 `python3 <技能目录>/scripts/audit.py "<运行目录>"`. 运行目录建在交付根目录下, 命名 `<域名> 上线体检 <日期>`. 网页读取工具会截断和转述, 结果最多 `partial`.

**模式 C: 不能跑 Python** → 按 `references/method.md` 的检查目录在对话里逐条人工核对, 给出同样结构的报告 (没有 PDF 和表格), 最多 `partial`.

## 第 3 步: 读结果

读 `原始数据/summary.json` 和 `audit.json` (字段见 `references/method.md`):

1. `status`: `complete` / `partial` / `failed`, 报告附录写同一个值.
2. `warnings`: 每一条都在报告里用大白话交代 (例如 "店铺不是 Shopify, 部分检查降级").
3. `verdict`: `go` 可以上线 / `fix_p0` 改完 P0 再上线 / `hold` 先别上线 / 空 = 无法判断.
4. `findings` 里 `unknown` 的写进"还有哪些没查清". **拿不到不等于不存在.**

## 第 4 步: 复核草稿, 写 report.md

`audit.py` 已写好草稿 `原始数据/report.draft.md`. 复制成 `原始数据/report.md` 后逐节复核:

- **前后说法对不上 (CNS 编号)**: 脚本用规则抽取, 会误判. 打开两段原文 (`claims.jsonl` 和 `raw/`) 确认说的是同一件事 (例如 "30 天质保" 不是退货期, 只针对某个国家的说法不算矛盾). 不是矛盾就删掉这条, 并同步从整改清单里去掉 (见下).
- 其他 P0 各看一眼原文; 明显误判就删或降级, 在附录说明.
- 把脚本的机械句子改成通顺大白话, 保留标签和编号; 正文不出现技术词 (自检会拦).
- 法规类结论只写 "与 X 的官方要求一致/不一致" 并标 `[推测]` + 依据; 不写法律结论词.
- 末尾固定结尾原样保留.

复核后确认是误判的条目, 用一条命令从清单里去掉 (会在原始数据里记为 "人工复核后排除"):

```bash
python3 <技能目录>/scripts/export_fixlist.py "<运行目录>" --drop CNS-02,GMC-08
```

## 第 5 步: 自检, 交付

```bash
python3 <技能目录>/scripts/check_report.py "<运行目录>"
python3 <技能目录>/scripts/deliver.py "<运行目录>"
```

- 自检有"错误"就按"怎么改"改完重跑, 直到没有错误; "提示/疑似标高"逐条处理, 改掉或在报告里说明为什么保留.
- `deliver.py` 生成 PDF (找不到浏览器时是 .html) 和 `整改清单.csv`. **没有 PDF 也没关系, HTML 就是正式交付物, 不要再去找别的 PDF 工具.**
- **失败也要交付**: 店铺打不开, 被拦截, 只有密码页, 不是网站, 都照样用草稿写一份短报告 (status 照实写 `failed` 或 `partial`, 写清卡在哪, 下一步怎么办), 过自检, 再 `deliver.py`. 不能只在对话里说一句.
- 交付后用大白话告诉用户文件在哪, 再给 5-8 行摘要: 结论, 最该先改的 3 条, 没查清的事, 并提醒"不是法律意见".

## 失败时

- 证书错误: 脚本已兼容, 不要关闭证书校验; 把提示转告用户.
- 被限流 (429): 加大 `--delay` (如 2) 重跑, 不要并发.
- `deliver.py` 失败: 报告仍在 `原始数据/report.md`, 告诉用户位置并在对话里给摘要.

## 参考文件

- `references/method.md`: 模式, 数据文件, 判定口径, 手动取数, 已知误判.
- `references/rules.json`: 检查目录 (编号, 级别, 市场, 依据来源 S 编号, 怎么改), 依据更新只改这里.
- `references/report-template.zh.md` / `.en.md`: 报告大纲, 写作要求, 固定结尾.
