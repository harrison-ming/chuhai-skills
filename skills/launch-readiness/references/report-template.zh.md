# 报告模板 (中文)

读者是不懂技术的出海卖家. `audit.py` 已按本模板生成草稿 `原始数据/report.draft.md`, 你的工作是复核和改写, 不是从零写.

## 写作要求 (写给 agent)

- 先结论后理由, 短句大白话; 正文不出现证据等级代号 (E1-E6) 和技术词 (多语言网址标注, 网站地图, 规范网址, 谷歌商家中心等用大白话), 技术细节放附录. 完整清单以 `scripts/check_report.py` 为准.
- 标签一字不差: `[已核实]` `[店铺自称]` `[第三方说法]` `[页面显示]` `[推测]` (同一行写 "依据: ...") `[有矛盾]` `[查不到]`. 宁可标低不要标高.
- **事实和法律判断分开标**: "退货政策写的是 7 天 [已核实]" 是事实; "与欧盟 14 天撤回权的官方要求不一致 [推测] 依据: 欧盟消费者权利指令 (来源 S5)" 是判断.
- **不写法律结论词** (检查脚本会拦), 写 "与 X 的官方要求一致/不一致", 且标 `[推测]`.
- `[有矛盾]` 必须引用两段原文; 复核后发现说的不是同一件事 (例如一处是质保期一处是退货期) 就删掉这条.
- 粘贴模式: 事实标 `[店铺自称]`, 注明 "来源: 你提供的文本"; 线上展示类检查写 `[查不到]`.
- 被拦截或超时写 `[查不到]`, 不能写 "没有".
- 附录写 `完成状态: complete` (或 partial / failed), 与 `summary.json` 一致.

## 大纲

```markdown
# <店名或域名> 上线体检报告

<sub><网址> · 检查日期 <YYYY-MM-DD> · <读取方式></sub>

## 一页看懂
- 按以下市场检查: <市场> (<来源>)
- 要改的: P0 <n> 条, P1 <n> 条, P2 <n> 条, P3 <n> 条
- 结论: **<可以上线 / 改完 P0 再上线 / 先别上线>** [推测] 依据: <P0 条数与编号>
- 这份体检对照的是官方公开要求, 不是法律意见.

**最该先改的 3 条**
1. <编号 问题: 怎么改>

## 先改这几条 (P0)
## 政策页
## 前后说法对不上
## 投谷歌购物广告前
## 各市场要求
## 多市场与翻译
## 看起来像没做完的地方
## 还有哪些没查清
## 附录: 证据与数据来源
- 完成状态: <complete/partial/failed>
<检查明细表, 依据清单 (来源名, 网址, 检索日期), 技术细节>
```

## 固定结尾 (附在附录之后, 原样保留)

```markdown
---

### 本报告没有覆盖的

- 需要浏览器才能看到的: Cookie 横幅实际弹出与同意前的数据发送, 购物车与结账页, 手机端效果.
- 需要后台才知道的: 谷歌商家中心设置, 支付开通, 税务登记, 物流时效的真实数据.
- 本报告对照的是检索日当天的官方公开资料, 只基于公开页面或你提供的文本, **不是法律意见**. 涉及法律义务 (欧盟/英国/加拿大/澳洲消费者法, 隐私法, 产品安全) 的事项, 上线前请找当地律师或合规服务商确认.

多市场全量检查, 浏览器实测, 整改复查对比: https://github.com/harrison-ming/chuhai-skills#进阶

<sub>由 launch-readiness (chuhai-skills) 生成</sub>
```
