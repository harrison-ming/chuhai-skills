# 报告模板 (中文)

读者是不懂技术的出海卖家. 写完删掉所有 `<...>` 提示.

## 写作要求 (写给 agent)

- 先结论后理由, 短句大白话; 数字带单位和币种, 比例写百分比.
- 正文不出现证据等级代号 (E1-E6) 和技术词, 技术细节放附录. 完整清单以 `scripts/check_report.py` 为准.
- 承重结论加标签, 一字不差: `[已核实]` `[店铺自称]` `[第三方说法]` `[页面显示]` `[推测]` (后跟 "依据: ...") `[有矛盾]` `[查不到]`. 宁可标低不要标高.
- 附录写 `完成状态: complete` (或 partial / failed), 与 `summary.json` 的 `status` 一致.

## 模板

```markdown
# <对象> __TITLE_ZH__报告

<sub><网址> · 检查日期 <YYYY-MM-DD></sub>

## 一页看懂

- <结论 1> <标签>
- <结论 2> <标签>
- <结论 3> <标签>

**最该先做的 3 件事**
1. <...>
2. <...>
3. <...>

**这份报告看不到什么**: <一句话>

## <检查项 1 的问题, 用卖家的话>
<结论一句, 然后 2-4 行理由, 带标签.>

## 还有哪些没查清
<哪些没拿到, 下一步怎么补. 拿不到不等于不存在.>

## 附录: 证据与数据来源

| 编号 | 等级 | 内容 | 来源 | 时间 |
|---|---|---|---|---|
| E01 | E1 | | raw/<文件> | |

- 完成状态: <complete/partial/failed>
- warnings: <原值>
```

## 固定结尾 (附在附录之后, 原样保留)

```markdown
---

### 本报告没有覆盖的

- <需要登录后台或浏览器实测才能看到的内容.>
- 本报告只基于公开信息, 是某一天的快照, 不构成尽职调查, 法律或财务意见.

<sub>由 __SKILL_NAME__ (chuhai-skills) 生成</sub>
```
