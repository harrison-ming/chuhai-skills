# 报告模板 (中文)

读者是不懂技术的出海卖家. `compute.py` 已经按本模板生成 `原始数据/report-draft.md`, 你的工作是复核和改写, 不是从头写.

## 写作要求 (写给 agent)

- 先结论后理由, 短句大白话; 金额带币种, 比例写百分比.
- 正文不出现证据等级代号 (E1-E6) 和技术词 (完整清单以 `scripts/check_report.py` 为准); 文件名, 接口, 字段名只放附录. 必须用到时带一句解释, 例: "账单显示名, 也就是买家信用卡账单上显示的商家名".
- 承重结论加标签, 一字不差: `[已核实]` `[店铺自称]` `[第三方说法]` `[页面显示]` `[推测]` (后跟 "依据: ...") `[有矛盾]` `[查不到]` `[你提供的]`. 宁低勿高.
- **图标和脚本只能写 `[页面显示]`**, 不能写成 "已开通/已连接"; 后台是否开通一律 `[查不到]`, 除非用户给了截图.
- 用户在对话里说的情况标 `[你提供的]`, 正文写 "你提供的: ...".
- 不打总分, 不判断能否过审, 不说 "保证/一定通过/不会被冻结"; 不给通道排名, 不放推荐或返佣链接.
- 优先级可以下调 (写一句理由), 不能上调成 "必然被拒/被冻结".
- `[有矛盾]` 两边原文并列写出.
- 附录写 `完成状态: complete` (或 partial / failed), 与 `summary.json` 的 `status` 一致.

## 模板

```markdown
# <店名> 收款体检报告

<sub><网址> · 检查日期 <YYYY-MM-DD> · 店面内容为从 <国家> 访问看到的版本</sub>

## 一页看懂

- 开户, 审核和风控结果由收款通道方决定; 本报告只列出能看到的问题.
- 体检状态: <完整/部分完成/没能完成>. 发现要改的: P0 x 条, P1 x 条, P2 x 条, P3 x 条; 没查清 x 项.
- 手续费估算: 每月约 <金额> <币种>, 一年约 <金额>, 占销售额 <x>% [推测] 依据: 你提供的客单价与单量 + 官方费率 (取数 <日期>).

**最该先改的几项**
1. [P0] <检查项>: <发现> <标签>

## 一. 先改这几项
| 优先级 | 问题 | 证据 | 怎么改 |
|---|---|---|---|

## 二. 收款主体与通道
## 三. 结账入口与支付方式
## 四. 政策页与一致性
## 五. 币种与多市场
## 六. 联系方式与信任信息
## 七. 手续费测算
<路径表 + 算法 + 合计 + 没算进去的 + 费率快照日期>

## 八. 还有哪些没查清
<拿不到不等于不存在; 下一步怎么补.>

## 附录 A: 证据表
- 完成状态: <complete/partial/failed>
- warnings: <原值>

## 附录 B: 费率来源
## 附录 C: 技术细节
## 附录 D: 你填写的问卷
```

## 固定结尾 (附在附录之后, 原样保留)

```markdown
---

### 本报告没有覆盖的

- 需要商家后台才知道的: 收款通道是否真的开通, 审核与风控状态, 实际合同费率, 冻结与拒付记录.
- 需要进入结账才看得到的: 结账页实际显示哪些付款方式, 各市场是否可用, 交易能否成功. 本工具不进入结账, 不下单.
- 税务 (销售税, 增值税), 公司注册, 外汇与资金出入境合规: 不在本报告范围, 请咨询持牌专业机构.
- 本报告基于公开页面和你提供的信息, 是某一天的快照, 不构成财务, 税务或法律意见. 收款账户的开通, 审核与风控结果由通道方决定, 本报告不作保证, 也不作任何经营结果或收益方面的承诺. 费率以通道方官方页面和你的合同为准.

多店体检, 浏览器实测结账前页面, 多种收款方案费用对比: https://github.com/harrison-ming/chuhai-skills#进阶

<sub>由 payments-readiness (chuhai-skills) 生成</sub>
```
