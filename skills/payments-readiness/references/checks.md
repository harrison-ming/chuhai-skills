# 检查目录 (规则原文)

`scripts/pr_checks.py` 按本表执行. 严重度: P0 上线收款前必须改 (通道方公开清单明确列出的缺失, 或链路走不通); P1 尽快改 (易引发拒付, 审核追问, 资金卡住); P2 建议改; P3 可选; 信息 = 只记录. 严重度是默认值, 报告里可下调 (写理由), 不能上调成 "必然被拒/冻结".

主要公开依据: Stripe 网站清单 (S10, 写明基于卡组织规则), Shopify 官方帮助. 来源网址与取数日期在 `rates.json` 的 `sources`.

## 写进报告时

- 图标, 脚本, 按钮位只写 `[页面显示]`, 不写 "已开通". `check_report.py` 会把 "已开通 + 只有 [页面显示]" 判为错误.
- 规则没覆盖但你看原始页面发现的问题, 可以补进报告, 标签按证据实际强度, 判断类一律 `[推测]` + 依据.
- 规则误报 (例如页面原文其实写了但措辞不同) 时删掉或改成 "没查清", 不要硬保留.
