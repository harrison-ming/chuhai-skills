# 利润与定价测算

帮不懂财务的出海卖家把一个商品 (最多两种售卖形态, 如单件和两件装) 的账算清楚: 每单贡献, 广告后利润, 盈亏平衡 ROAS 和最高获客成本, 底线价和目标价, 三情景, 全店月固定成本, 开张现金, 最要命的 3 个输入. **数字全部由脚本按公式算, 你不要自己心算或改数字**; 你的分工是把用户的话整理成输入表, 跑脚本, 再用大白话转告结果.

## 边界 (先读)

- 只算用户给的数字和随技能附带的费率表. **不预测销量, 不承诺收益, 不替用户决定做不做**, 判断一律 `[推测]` + 依据.
- 不做关税归类, 不猜税率: 用户没给关税就按 "未含关税" 算并写明.
- 汇率不内置: 用户给的优先; 没给且能联网时脚本自动取欧洲央行带日期的参考汇率; 都没有就请用户补.
- 每个默认值都会出现在报告的 "假设清单" 里, 不允许悄悄补值.
- 不构成财务, 税务或法律意见.

## 第 0 步: 检查 Python

脚本要用电脑上的 Python 3.8+. 先查一次, 用第一个输出 `Python 3.x` (x ≥ 8) 的命令, 下文示例里的 `python3` 都换成它:

```bash
python --version
python3 --version
py -3 --version
```

- macOS / Linux 一般是 `python3`; **Windows 一般是 `python` 或 `py -3`, 不是 `python3`**.
- 没装 Python 的 Windows 会输出 "Python was not found; run without arguments to install from the Microsoft Store..." (退出码 9009). 这算**没有 Python**, 不是成功.
- 三个都不行时, 用大白话告诉用户怎么装 (Windows: 命令行输入 `python` 打开应用商店点"获取"; 或到 python.org 下载, 安装第一屏勾选 "Add python.exe to PATH"), 装好后重开 AI 助手再继续.
- 用户不想装: 走模式 C (手算), 这时没有 PDF 和表格.

## 第 1 步: 收集输入 (问卷)

**用户已经在对话里给了数字, 就直接用, 不要再追问.** 缺的非必填项不用问, 脚本会按假设清单补并在报告里写明. 只有必填项缺失时才问**一次**, 一次问齐; 当前环境不能来回对话 (一次性任务) 时不要问, 直接跑, 报告会列出 "需要你补的".

必填 (★): 销售市场 (US / UK / EU-DE ...), 汇率 (1 美元 = ? 元; 没有可留空让脚本取欧洲央行汇率), 收款方式 (Shopify Payments / Stripe / PayPal 中国账户 ...; 或直接给收款费率), 售价, 采购单价, 尾程运费. 欧盟和英国市场另需增值税率.

建议问的 (按这个顺序, 一句话问完): 包装, 头程, 关税合计税率 (按货值还是按售价), 拣货打包, 仓储, 退货率, 退货运费, 退回货能再卖的比例, 获客成本或 ROAS, Shopify 套餐与月费, 插件月费, 首批数量与打样费等启动项.

全部字段, 单位和缺失时的处理见 `references/inputs.md`.

## 第 2 步: 写输入表并运行 (模式 A, 首选)

脚本在本技能目录的 `scripts/` 下, 只用 Python 标准库.

1. 建运行目录 (用商品名):

```bash
python3 <技能目录>/scripts/profit.py init --product "宠物梳"
```

它会打印**运行目录**和**输入文件**路径 (`<运行目录>/原始数据/inputs.csv`, 英文是 `data/`). **用户没指定保存位置时不要加 `--out-root`**, 也不要写到当前目录: 默认存到 "文档/出海利润测算"; 环境里已有 `CHUHAI_OUTPUT_DIR` 时脚本自动用它, **不要自己设置, 覆盖或改写这个变量**, 命令前也不要加任何环境变量.

2. 把输入**整个覆盖写入**这个 inputs.csv (UTF-8). 一行一个数, 列为 `商品,项目,基准,保守,乐观,单位,来源说明`; 店铺级的项 (市场, 汇率, 收款, 月费, 启动项) 商品写 `全店`; 金额必须写单位 `CNY` 或售价币种; 百分比写 `15` 表示 15%; 保守/乐观 只有用户给了区间才填. 例:

```csv
商品,项目,基准,保守,乐观,单位,来源说明
全店,销售市场,US,,,,
全店,汇率,7.20,,,CNY,用户给的
全店,收款方式,Shopify Payments,,,,
全店,收款费率,2.9,,,%,
全店,收款每笔固定费,0.30,,,USD,
全店,Shopify 套餐,Basic,,,,
全店,套餐月费,39,,,USD,
宠物梳,售价,39.99,,,USD,
宠物梳,采购单价,45,,,CNY,
宠物梳,头程,12,,,CNY,
宠物梳,关税合计税率,25,,,%,
宠物梳,关税计税基数,按货值,,,,
宠物梳,尾程运费,5.5,,,USD,
宠物梳,退货率,8,,,%,
宠物梳,获客成本,10,,,USD,
```

用户说的无效值 (如 "折扣 120%") **照原样写进去**, 不要自己改, 脚本会按规则处理并在报告 "请核对" 里写清楚. 用户没说的项不要写行, 也不要自己编值.

3. 运行 (校验 → 计算 → 报告 → 自检 → 交付):

```bash
python3 <技能目录>/scripts/profit.py run "<运行目录>"
```

用户用英文提问时 `init` 和 `run` 都加 `--lang en`. 不能联网或不想取欧洲央行汇率时加 `--no-fx-fetch`. 想在后台运行不打开文件夹加 `--no-open`.

用户直接给了一份填好的 CSV (例如用 `templates/inputs-template.zh.csv` 填的), 直接 `run <那个 csv 路径>`, 脚本会建运行目录并复制进去.

## 第 3 步: 读结果

`run` 最后打印完成状态和每个商品的关键数字, 报告和表格已经生成.

- `complete`: 全部按用户数字算出. `partial`: 用了关键默认 (退货率试算档, 欧洲央行汇率) 或缺关税, 或有商品没算出来. `failed`: 一个商品都算不出 (缺必填项或数字无效), 报告里有 "需要你补的".
- 如果打印了自检 "错误" 或 "提示", 逐条看: 报告是脚本生成的, 一般不会有; 有的话把原文告诉用户, 不要自己改数字.
- **报告里的数字不要改, 也不要在对话里给出报告里没有的数字.** 想换个价格或成本看看, 改 inputs.csv 再 `run` 一次.

## 第 4 步: 告诉用户

用大白话说文件在哪 (例: "报告在 文档 → 出海利润测算 → 宠物梳 利润测算 2026-10-27, 双击 PDF 看; 每单测算.csv 等表格能用 Excel 打开"), 再给 5-8 行摘要: 每单赚/亏多少, 广告后利润, 盈亏平衡 ROAS 与最高获客成本, 底线价与目标价, 最要命的输入, 用了哪些默认值 (尤其 "未含关税", 退货率试算档), 需要补什么. 说清楚这些是 "按你给的数字算" 的条件结果, 不是收益预测.

**生成的是 .html 不是 .pdf 也完全可以** (电脑或沙箱里没有 Edge/Chrome 时就是这样): 告诉用户双击用浏览器打开, 需要 PDF 在浏览器里 打印 → 另存为 PDF. 不要去找或安装别的 PDF 工具.

## 其他模式

**模式 C: 不能运行 Python** → 按 `references/method.md` 的公式 F1-F12 逐步手算 (全程保留至少 4 位小数, 最后按其中的取整规则取整), 按 `references/report-template.zh.md` (英文 `.en.md`) 的结构在对话里给完整报告, 开头注明 "手算, 未经脚本校验", 完成状态最多 `partial`, 末尾原样附固定结尾. 没有 PDF 和表格.

**模式 D: 用户把数字粘贴成表格或截图文字** → 整理成第 2 步的 inputs.csv 后走模式 A; 不能运行 Python 时走模式 C.

## 失败时

- 输入有问题 (缺必填项, 售价不是数字, 币种没写): 照样 `run`, 会交付一份 `failed` 或 `partial` 报告, 把 "需要你补的" 转告用户, 补上后再跑.
- `run` 报 Python 错误: 把错误原文告诉用户, 换模式 C 手算并说明.
- 交付失败: 报告仍在 `<运行目录>/原始数据/report.md`, 告诉用户位置, 在对话里给摘要.
