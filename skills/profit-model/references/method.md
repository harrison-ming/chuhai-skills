# 方法: 利润与定价测算

写给 agent 看. 模式 A 由脚本 (`profit.py run`) 完成全部计算; 模式 C 不能运行 Python 时按本文逐条手算. 字段和缺失处理见 `inputs.md`.

## 1. 记号 (每单; 金额先换算成售价币种: 人民币金额 / 汇率)

| 记号 | 定义 |
|---|---|
| u | 每单件数 |
| G 买家实付 | 售价 x (1 - 折扣) + 向买家收的运费 (广告后台 ROAS 用的口径); 售价是这个售卖形态的标价, 两件装填套装价, u 只影响货本 |
| N 净收入 | G / (1 + 增值税率); 美国增值税 = 0 (销售税另收, 不进模型) |
| V 计税货值 | u x (采购单价 + 包装) |
| L 落地货本 | V + u x 头程 + 关税; 关税 = 计税基数 x 关税税率 + 每单固定税费, 计税基数 = V (按货值) 或 N (按售价) |
| F 履约 | 拣货打包 + u x 仓储 |
| Pay 收款费 | G x (收款费率 + 第三方交易费 + 跨境卡附加 + 结汇价差) + 每笔固定费 |
| r, k | 退货率, 退回货可再售比例 |

## 2. 公式 (编号与报告附录一致)

- **F1** G, N 如上.
- **F2** L 如上.
- **F3 每单贡献 (广告前)**, 退款口径: `CM0 = N x (1 - r) - L x (1 - r x k) - F - 尾程 - r x 退货运费 - Pay - 其他`. 退款冲回净收入, 收款费不退 (Shopify Payments, Stripe, PayPal 美国官方页均写明原交易费不退; Shopify 第三方交易费的退还条件有矛盾, 按不退计). 补发口径: 不冲收入, 另付 `r x [(1 - k) x L + F + 尾程] + r x 退货运费` (补发那一单的拣货和运费总要付).
- **F4 贡献率**: CM0 / N (会计口径) 和 CM0 / G (广告口径), 两个都给.
- **F5 盈亏平衡 ROAS** = G / CM0; CM0 ≤ 0 时 "无解: 不投广告也亏". 目标 ROAS = G / (CM0 - 目标利润率 x N).
- **F6 最高获客成本** = CM0; 目标获客成本 = CM0 - 目标利润率 x N.
- **F7 广告后每单利润** CM1 = CM0 - 获客成本; 只给 ROAS 时 获客成本 = G / ROAS; 都没给时不算 CM1.
- **F8 盈亏平衡月单量** = 月固定合计 / CM1, 向上取整; CM1 ≤ 0 时 "无解".
- **F9 启动现金** (主路线): 首批数量 x (采购 + 包装) + 首批数量 x 头程 + 首批关税 (按货值时 = 首批货款 x 税率; 按售价时随单付, 不预付) + 打样 + 保证金 + 入仓费 + 月固定合计 x 回本前月数 + 测款广告. 最省路线: 最小起订量的货款 + 打样 + 保证金 + (月固定 - 海外仓月最低消费) x 回本前月数 + 测款广告 (直邮, 无头程, 无入仓费). 缺的项标 `[查不到]`, 合计写 "已知项合计".
- **F10 底线价与目标价**: 其他输入固定时, `CM1 - 目标利润率 x N` 是售价的一次函数 (折扣, 费率, 按售价计税, 由 ROAS 推出的获客成本都按比例). 取售价 10 和 100 两点求斜率和截距, 解出底线价 (目标利润率 = 0) 和目标价. 没有获客成本时 CM1 用 CM0, 写明 "不含广告". 建议标价 = 目标价向上取到 .99 尾数.
- **F11 现金周期** = 库存天数 + 回款天数 - 付款天数; 库存天数 = 运输天数 + (首批数量 / 日销件数) / 2; 付款天数 = -(生产天数 x 定金比例) (先付定金为负). 缺项时只列公式和已知项.
- **F12 敏感度**: 每个金额, 百分比输入和汇率单独 x 1.1 与 x 0.9 (相对值), 其余取基准, 记录 CM1 变化, 按绝对影响降序. 售价是 "你能控制的杠杆", 其余是 "成本风险"; 获客成本, ROAS, 目标利润率, 件数不参与排名; 值为 0 的项跳过. 关税另出 "+10 个百分点" 一行. 免费版报告写前 3 名.
- **三情景**: 保守 / 基准 / 乐观每列用对应列的值整体重算 (不是在基准上加减), 空列回落基准; 报告列出每个情景与基准不同的假设.

## 3. 数值与取整

- 全程十进制精确计算, 不经二进制浮点; 手算时中间值保留至少 4 位小数.
- 只在展示时取整: 金额四舍五入到 0.01, 百分比到 0.1. **盈亏平衡 ROAS, 底线价, 目标价向上取到 0.01; 最高获客成本向下取到 0.01; 单量向上取整**. 方向一律偏保守.
- 不同币种不能直接相加, 先换算.

## 4. 证据标签 (最弱一环)

| 标签 | 用于 |
|---|---|
| `[你提供的]` | 用户填的数字, 以及只依赖用户数字的结果 |
| `[已核实]` | 费率表里 verified 且采集不超过 180 天的条目, 带日期的欧洲央行汇率; 同一行必须写出日期 |
| `[推测]` + 依据 | 默认值, 试算档, 套餐或主体是假设的费率表取值, 以及一切判断 ("广告空间偏窄") |
| `[有矛盾]` | 费率表 conflict 条目 (如 TikTok 佣金 6% 与第三方说的 8%) |
| `[查不到]` | 缺关税, 缺首批数量等算不出的项 |

结果的标签 = 依赖链上最弱的一个: `[查不到]` < `[推测]` < `[你提供的]` < `[已核实]`. 缺关税时关税本身标 `[查不到]`, 依赖它的结果按 "未含关税" 的假设标 `[推测]`. 依据写假设编号 (A1, A2 ...).

## 5. 费率表

`data/fee_tables.json`, 顶层 `valid_as_of`, 每条有 `retrieved` (采集日), `valid_as_of` (官方页更新日, 可空), `status`. 距采集超过 90 天提醒复核, 超过 180 天降为 `[推测]`. unverified 条目 (TikTok 新卖家 3%, 退款管理费) 永不作为默认值. 用户填的费率永远优先, 与表不同时报告注明 "以你的为准". 刷新: 人工按每条 `source_url` 复核 (美国价须从美国出口取), 不自动抓.

## 6. 完成状态

| 状态 | 条件 | 脚本退出码 (`pm_calc.py`) |
|---|---|---|
| complete | 全部商品算出, 没有关键默认 | 0 |
| partial | 有商品被阻断, 缺关税, 退货率用试算档, 汇率取自欧洲央行, 用到超过 180 天的费率, 或收款费率按假设主体取表 | 2 |
| failed | 一个商品都算不出 | 3 |

折扣 0, 买家运费 0 这类 "没提供按 0" 的默认进假设清单, 但不降状态. `profit.py run` 交付成功即返回 0, 状态打印在最后.

## 7. 模式 C 手算步骤

1. 列出输入并按 `inputs.md` 补默认, 每个默认编号写进 "假设清单".
2. 按 F1-F7 算基准情景, 再按保守 / 乐观列重算; 按 F8-F11 算店铺级.
3. 按 F12 至少算售价, 汇率, 采购单价, 尾程运费四项的 ±10%, 排出前 3.
4. 按 `report-template.zh.md` 的结构写报告, 开头注明 "手算, 未经脚本校验", 完成状态最多 partial.
