# 商业分析方法 (L1)

平台无关的商业拆解. Shopify 技术层见 `shopify-checks.md`. 目标不是评价"网站好不好看", 而是回答: 它卖给谁, 顾客为什么愿意付这个价, 页面怎么推动购买, 哪些做法值得借鉴.

## 1. 观察条件 (报告必须声明)

访问日期与时区; 最终落地 URL; 观察的国家, 语言, 币种; 桌面还是移动; 是否登录 (默认否); 价格是否含税; 哪些页面因地区, 弹窗或拦截没看到. 同一个店在不同市场可能展示不同的价格, 商品和政策, **不能把一个地区的观察推广到全球**.

## 2. 定位

回答五个问题: 服务谁? 在什么场景买? 解决功能问题, 情绪问题还是身份表达? 希望顾客记住什么差异? 用什么证据支撑差异?

证据来源: 首屏标题和 CTA, 商品命名和分类, About 页, 商品详情和材料说明, 评价和 UGC, 媒体背书.

输出一句话定位:

```text
为 [具体人群] 在 [具体场景] 提供 [商品/结果], 主要通过 [差异与证据] 支撑 [价格或选择理由].
```

## 3. 商品系统

- **架构**: 核心品类与辅助品类; 集合按什么组织 (材质, 用途, 场景, 价格, 新品); 商品数量与选择负担; 有没有引流款, 主力款, 高价锚点, 限量款, 套装.
- **差异来源**: 原材料, 工艺, 设计, 功能, 定制, 稀缺, 服务, 品牌故事, 交付速度. 外观与通用供应链高度相似时, 需要进一步找溢价证据, **不要直接断言"贴牌"或"原创"**.
- **变体与决策成本**: 尺码, 颜色, 材料选项是否好懂, 有无默认推荐和尺码指南. 变体多不等于体验好.
- **上新节奏**: 用 `summary.json` 的 `published_by_month` 看近 12 个月每月上新数, 判断是持续上新, 季节性集中还是长期不更新.

## 4. 定价与促销

优先用 `summary.json` 的全量统计 (不用抽样):

- 最低价, p25, 中位价, p75, 最高价; 价格带分布.
- 折扣: 打折商品占比, 折扣深度中位数. 占比很高说明折扣是常态而非活动.
- 分析: 价格梯度是否清楚; 高价商品怎么解释价值; 免费配送门槛是否推动加购; 有无稀缺, 倒计时, 套装.

**没有成本, 广告费, 退货率数据时, 不计算也不断言利润率.** 可以做假设模型, 但必须公开假设.

## 5. 首页转化路径

按用户阅读顺序:

```text
首屏识别 → 商品或场景兴趣 → 差异解释 → 社会证明 → 商品入口 → 风险消除 → 行动
```

每一段回答: 想让用户知道什么? 给了什么证据? 把用户引到哪? 与上下段是否连贯? 有无过早要邮箱, 弹窗过多, CTA 互相冲突? 不把视觉风格本身当作转化逻辑.

## 6. 商品详情页 (至少 3 个)

从价格分布里挑: **入门款** (接近 p25 或最低价) / **主力款** (接近中位价, 或 best-selling 排序靠前) / **高价或差异化款** (接近最高价).

按这个顺序分析:

```text
我买的是什么 → 为什么适合我 → 为什么值这个价 → 为什么可信 → 买错了怎么办 → 现在怎么买
```

检查: 首屏是否说清商品, 价格, 主要选项和按钮; 图片, 视频, 细节图, 场景图; 材料, 规格, 尺码, 护理, 产地; 配送与退货信息的位置; 评价和 UGC; 保证和认证; 搭配推荐.

## 7. 信任系统

| 顾客的顾虑 | 可能的证据 |
|---|---|
| 品牌是否真实 | 公司名, 地址, 团队, 联系方式, 站外账号 |
| 商品是否如描述 | 细节图, 规格, 评价, UGC, 认证 |
| 能不能收到货 | 配送范围, 时效, 物流追踪说明 |
| 买错怎么办 | 退换货, 尺码调整, 保修 |
| 支付是否安全 | HTTPS, 结账说明 (图标只是声明, 不是证明) |
| 高价是否合理 | 材料, 工艺, 来源, 定制, 服务证据 |

## 8. 本地化与履约

- 国家, 语言, 币种是否一致; 翻译是否覆盖导航, 商品, 政策; 尺码, 单位, 税费, 关税说明是否适配目标市场. "能切换语言"不等于完成本地化.
- 公开的履约承诺: 处理时间与运输时间, 免邮门槛, 退换窗口, 预售和定制说明, 客服入口. **这些是承诺, 不是实际履约表现.**

## 9. 站外核验

L0 做前三项, L1 做全部. 每条附 URL 和访问日期.

| 项目 | 方法 | 纪律 |
|---|---|---|
| 域名年龄 | RDAP (`summary.json` 的 `offsite.rdap`) | 注册日期不等于开店日期 |
| 历史快照 | Wayback CDX (`offsite.wayback`) | 把首次抓取, 品牌自称的成立年份, 首个商品 `created_at` 三方对照 |
| 独立评价平台 | Trustpilot, REVIEWS.io 等 | 与站内评价数对比; 差距只标 `[有矛盾]`; 记录主页是否被商家认领 |
| 公司登记 | 所在国公开登记库 | 默认不买付费摘录 |
| 广告库 | Meta Ad Library, TikTok Creative Center | 需要浏览器; 没实际看到就写 `[查不到]` |
| 流量估算 | Similarweb 等 | 只写区间, 标 `[第三方说法]`, 不当渠道事实 |
| 投诉 vs 政策 | 把站外投诉主题与政策原文对照 | 投诉可能正好是政策设计的结果 (例如只对部分国家包税), 不一定是偶发事故 |

网络受限 (例如在中国大陆访问 archive.org) 时, 该项写 `[查不到]` (数据源不可达), 不影响其他结论.

## 10. 可迁移策略

每条建议归入: **直接学** (原则适用, 可直接用) / **改一改再学** (值得用, 需按自己的品类改造) / **先小范围试** (有潜力, 要实验验证) / **别学** (有风险或只适合该品牌). 证据不足的不写成建议, 放进"还有哪些没查清".

每条建议写清 (对应报告表格的列): 做法 (附观察到的证据) / 为什么有用 / 适合什么情况 / 花多少功夫 (低/中/高) / 怎么看效果 / 风险. 另列"不建议照搬的部分": 只适合该品牌, 依赖特殊资源, 或证据不足的做法.
