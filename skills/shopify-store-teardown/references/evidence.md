# 证据与结论纪律

报告里每一条会影响判断的结论, 都要能追溯到证据. 宁可写 `[查不到]`, 不要猜.

## 1. 证据等级

| 等级 | 是什么 | 例子 | 能证明什么 |
|---|---|---|---|
| E1 | 当前页面的直接证据 | 公开 JSON 端点, 页面源码, 当前价格和政策原文 | 此时此刻页面上是这样 |
| E2 | 品牌自己的一手说法 | About 页, 官方社媒, 品牌声明 | 品牌怎么说; 收入/销量/产地/效果类说法仍需核验 |
| E3 | Shopify 官方资料 | help.shopify.com, shopify.dev | 平台**能**做什么, 不证明这家店**做了** |
| E4 | 可追溯的第三方记录 | RDAP 域名登记, Wayback 快照, 公司登记库, 权威媒体 | 第三方记录显示如此 |
| E5 | 未经验证的第三方说法 | 视频/文章/帖子里的收入和成本, 流量估算工具 | 只能当线索 |
| E6 | 分析推断 | 对商业机制和用户心理的解释 | 必须写出依据 |

## 2. 报告用语 ↔ 证据等级

报告读者是不懂技术的卖家. **正文**的承重结论前加下面的大白话标签 (一字不差, 半角方括号, 交付脚本会把它们渲染成彩色徽章); **附录的证据表**写 E1-E6 等级. 两者按此表对应:

| 正文标签 | 对应等级 | 什么时候用 |
|---|---|---|
| `[已核实]` | E1-E4 | 当前页面原文, 商品数据, 注册记录, 本次抓到的权威媒体原文能直接支持 (分析判断不算) |
| `[店铺自称]` | E2 | 品牌自己的说法 (About 页, 宣传语, 自称年份/认证) |
| `[第三方说法]` | E5 | 未经验证的第三方说法: 测评, 视频, 流量估算, 评价平台 |
| `[页面显示]` | E1 (仅表面) | 页面上出现了某个东西, 但不代表后台状态. 支付图标, 应用脚本专用 |
| `[推测]` | E6 | 分析解释, 必须紧跟一句 "依据: ..." |
| `[有矛盾]` | - | 有两条互相冲突的证据 (只是缺数据用 `[查不到]`) |
| `[查不到]` | - | 现有证据回答不了 |

### 2.1 标签宁低勿高

正文和"一页看懂"一律适用:

1. **一条结论混了不同等级的说法, 拆开分别标.** 例: "店铺自称 2016 年创立 [店铺自称], 网站注册记录显示域名 2015 年注册 [已核实]", 不要整句只标一个 `[已核实]`.
2. **分析判断用 `[推测]`, 即使依据是核实过的数据.** `[已核实]` 只用于能直接追溯到某个页面原文, 数据字段或登记记录的事实 ("在售 132 款", "退货期 30 天"). "定价能成立是因为材料故事" "主力价位带是刻意设计的" 都是判断, 写 `[推测]` + "依据: ...".
3. **不凭记忆引用外部事实.** 融资, 上市, 营收, 门店数, 创始人经历等, 本次没有抓取到来源页面的, 要么不写, 要么写 `[查不到]` 并说明"未核实". 不能标 `[已核实]` 或 `[第三方说法]`.
4. **附录等级同样宁低勿高.** 没有实际抓取的"公开报道", "众所周知"不能标 E3/E4; 本次抓到并存档的第三方页面才算 E4, 未经验证的说法最多 E5, 分析一律 E6.
5. **`[有矛盾]` 只用于有两条互相冲突的证据** (例如商品页写 30 天退货, 政策页写 14 天). 只是缺数据, 取不到, 不确定, 用 `[查不到]`.

写完后 `scripts/check_report.py` 会把带判断用语 (核心, 基本, 所以, 说明了等) 或混入 "自称" 的 `[已核实]` 标成"疑似标高", 逐条按上面第 1-2 条复查.

旧版报告的 `[事实]` `[品牌自述]` `[第三方声称]` `[观察]` `[推断]` `[存疑]` `[未知]` 依次对应上表各行, 新报告不再使用.

## 3. 空值纪律

- `null`: 应该取得但没取得 (请求失败, 页面打不开).
- `not_observed`: 看了, 没出现.
- `unknown`: 看了, 判断不了.
- `false`: 有证据明确表明"否".

**`not_observed` 不等于 `false`.** 例: 首页源码里没找到 Klaviyo, 只能写"未观察到", 不能写"没用 Klaviyo".

## 4. 冲突处理

1. 两边说法都保留.
2. 当前直接证据 (E1) 优先于历史资料.
3. 检查是不是时间, 市场, 登录状态或缓存造成的差异.
4. 不用推断去"消除"解释不了的冲突.
5. 标 `[有矛盾]`, 写出下一步怎么验证.

## 5. 结论纪律

- 相关不等于因果.
- 漂亮不等于转化高.
- 售罄标签不等于真实销量.
- 评价多不等于评价真实; 站内外评价数有差距只能标 `[有矛盾]`, 不等于刷评.
- 支付图标不等于已开通.
- 价格高不等于利润高; 没有成本数据时不估算利润率.
- 网站开得久不等于现在经营得好.
- 域名注册日期不等于开店日期.
- 别人在视频里展示一家店, 不等于他拥有或搭建了这家店.

## 6. 完成状态

| 状态 | 条件 |
|---|---|
| complete | 所选档位要求的数据和页面都拿到了, 身份判断明确, 承重结论都能追溯 |
| partial | 有可用结论, 但有明确缺口 (某端点被拦, 政策页缺失, 商品样本不够, 身份只到 probable) |
| failed | 身份无法确认, 页面打不开, 或证据不足以回答研究问题 |

失败也要交付: 写清楚卡在哪, 下一步可以怎么试.

## 7. 时效

价格, 库存, 促销, 主题, 应用, 政策, Shopify 平台能力都会变. 报告里引用这些信息时带上采集日期; 旧报告只代表当时的快照.
