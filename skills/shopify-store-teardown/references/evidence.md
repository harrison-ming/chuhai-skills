# 证据与结论纪律

报告里每一条会影响判断的结论, 都要能追溯到证据. 宁可写"未知", 不要猜.

## 1. 证据等级

| 等级 | 是什么 | 例子 | 能证明什么 |
|---|---|---|---|
| E1 | 当前页面的直接证据 | 公开 JSON 端点, 页面源码, 当前价格和政策原文 | 此时此刻页面上是这样 |
| E2 | 品牌自己的一手说法 | About 页, 官方社媒, 品牌声明 | 品牌怎么说; 收入/销量/产地/效果类说法仍需核验 |
| E3 | Shopify 官方资料 | help.shopify.com, shopify.dev | 平台**能**做什么, 不证明这家店**做了** |
| E4 | 可追溯的第三方记录 | RDAP 域名登记, Wayback 快照, 公司登记库, 权威媒体 | 第三方记录显示如此 |
| E5 | 未经验证的第三方说法 | 视频/文章/帖子里的收入和成本, 流量估算工具 | 只能当线索 |
| E6 | 分析推断 | 对商业机制和用户心理的解释 | 必须写出依据 |

## 2. 结论标签

报告中的承重结论前面加标签:

- `[事实]` E1-E4 能直接支持.
- `[品牌自述]` 品牌自己的说法.
- `[第三方声称]` E5 类说法.
- `[观察]` 页面上显示了某个东西, 但不代表后台状态 (支付图标, 应用脚本专用).
- `[推断]` 分析解释, 必须紧跟一句"依据: ...".
- `[存疑]` 证据互相冲突, 或存在其他解释.
- `[未知]` 现有证据回答不了.

## 3. 空值纪律

- `null`: 应该取得但没取得 (请求失败, 页面打不开).
- `not_observed`: 看了, 没出现.
- `unknown`: 看了, 判断不了.
- `false`: 有证据明确表明"否".

**`not_observed` 不等于 `false`.** 例: 首页源码里没找到 Klaviyo, 只能写"未观察到", 不能写"没用 Klaviyo".

## 4. 冲突处理

1. 两边说法都保留.
2. 当前直接证据 (E1) 优先于历史资料.
3. 检查是不是时间, 市场, 登录状态或缓存造成的差异.
4. 不用推断去"消除"解释不了的冲突.
5. 标 `[存疑]`, 写出下一步怎么验证.

## 5. 结论纪律

- 相关不等于因果.
- 漂亮不等于转化高.
- 售罄标签不等于真实销量.
- 评价多不等于评价真实; 站内外评价数有差距只能标 `[存疑]`, 不等于刷评.
- 支付图标不等于已开通.
- 价格高不等于利润高; 没有成本数据时不估算利润率.
- 网站开得久不等于现在经营得好.
- 域名注册日期不等于开店日期.
- 别人在视频里展示一家店, 不等于他拥有或搭建了这家店.

## 6. 完成状态

| 状态 | 条件 |
|---|---|
| complete | 所选档位要求的数据和页面都拿到了, 身份判断明确, 承重结论都能追溯 |
| partial | 有可用结论, 但有明确缺口 (某端点被拦, 政策页缺失, 商品样本不够, 身份只到 probable) |
| failed | 身份无法确认, 页面打不开, 或证据不足以回答研究问题 |

失败也要交付: 写清楚卡在哪, 下一步可以怎么试.

## 7. 时效

价格, 库存, 促销, 主题, 应用, 政策, Shopify 平台能力都会变. 报告里引用这些信息时带上采集日期; 旧报告只代表当时的快照.
